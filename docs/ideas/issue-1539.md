# KillSwitch Sentinel — A Consent-Gated Emergency Brake for Deployed AI Systems

Tracking issue: [#1539](https://github.com/ava-agent/awesome-ai-ideas/issues/1539)

## 摘要
KillSwitch Sentinel 面向已部署 AI 系统的运营方与合规团队，提供一个"同意门控"的紧急制动层：在检测到严重异常（越权调用、危险输出、成本失控、审计违规）时，能够按预设策略触发分级熔断——从降级、限流到完全停机——并要求受影响相关方（模型所有者、业务负责人、监管接口）按最小同意集合联签解除，避免单点误触或恶意关停。

## 目标用户
- 部署 LLM / Agent 系统的产品团队与 SRE
- AI 安全 / 合规 / 风控团队
- 需要向监管方证明"可停机"能力的行业客户（金融、医疗、政企）

## 核心价值
1. **可证明的停机能力**：为监管与审计提供机器可验证的紧急制动 SLA。
2. **减少误伤**：分级熔断 + 多方同意，避免恐慌式全量下线。
3. **事后可追溯**：所有触发、同意、恢复动作生成不可篡改事件链，可对接 SIEM。

## 技术方向
- Sidecar / Gateway 拦截推理与工具调用流量，基于策略引擎（OPA / Cedar）判定
- 阈值信号：输出安全分类器、成本与调用速率、外部反馈通道（用户举报、上游告警）
- 同意协议：门限签名或 M-of-N 审批工作流，与 IdP / 值班系统集成
- 事件链：Append-only log，可选锚定到内部审计存储或公链哈希

## MVP 范围
- 单一 LLM 网关的 kill-switch 中间件（拒绝 + 排空 + 冻结会话）
- YAML 策略与两方同意的解除流程
- 与 Slack / PagerDuty 的通知与审批回执

## 开放问题
- 与现有 Feature Flag / Circuit Breaker 生态的边界与集成方式
- 同意机制在跨组织场景（供应商 vs 客户）的信任模型
- 熔断粒度：会话级、租户级、模型级、区域级的策略组合

## 参考评估维度
- 用户价值：合规刚需，尤其在受监管行业
- 技术可行性：现有网关 + 策略引擎技术栈可组合实现，MVP 门槛低
- 商业模式：面向企业订阅 + 合规审计报告增值服务
